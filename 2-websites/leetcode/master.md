# 중요
## 결정한 사항
- 소스코드는 LeetCode 플랫폼이 아닌 Git에서 관리
- 모든 문제는 해설 보기 전 먼저 시도하고 `자력` 여부 기록
- 같은 문제의 여러 풀이는 파일을 나누지 않고 하나의 파일 안에 병합
- 빈출 알고리즘 템플릿은 기존의 파일을 사용, 필요시 수정 (`problem-solving/3-others/snippets`)

## 푸는 절차
1. **조건 확인 + 복잡도 계산**: 조건을 빠짐없이 적고, 제약조건에서 목표 복잡도를 역산한다
2. **순서도 그리기 + 풀이 요약 작성**: 노트에 흐름을 그리고 (암산 금지), 주석으로 풀이를 먼저 쓴다
3. **반례 찾기**: 그리디·DP라면 착수 전에 반례부터 찾는다
4. **주석 아래 채우기**: 요약해둔 주석을 그대로 코드로 옮긴다
5. **엣지 케이스 넣어보기**: 최소·최대 입력을 넣고, 1번의 조건 목록과 대조한다

## 막혔을 때
1. 조건을 재확인한다 (혼자서만 더 어려운 제약을 두고 있진 않은지)
2. 접근법을 바꾼다 (원인을 못 짚은 채 조건만 바꿔보고 있으면 접근이 틀린 것)
3. 브루트포스라도 완성한다 (부분점수 확보 + 최적화의 출발점)
4. 연습 중이라면 1시간에서 끊고 답을 본다 → `review-notes.md`에 기록

## 유형 정리
1. 기본 접근
    - 구현, 시뮬레이션
    - 완전탐색, 백트래킹

    - DP
2. 그래프
    - DFS/BFS
    - 최단경로
    - 유니온 파인드, MST
    - 위상정렬

3. 자료구조
    - 해시
    - 스택, 큐, 덱, 우선순위 큐
    - 연결 리스트
4. 기법
    - 이분탐색, 파라메트릭 서치
    - 투포인터, 슬라이딩 윈도우

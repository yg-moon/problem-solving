# 결론
기록 전체에서 나온 것. 본문 항목의 발췌가 아니므로 문제가 쌓여도 여기는 잘 바뀌지 않는다.

1. **몰라서 못 푼 게 아니라 못 알아봐서 못 풀었다.**
    - 「내가 놓쳤던 단서들」의 정답은 전부 표준 유형이었고, 유형은 17개뿐이다. 새 알고리즘을 배우는 것보다 단서를 외우는 것이 이득이다.
2. **안 보이면 뒤집는다.**
    - 방향 → 구하는 대상 → 수행 여부 순으로. 이 하나로 풀린 문제가 가장 많다.
3. **안 풀리면 상태를 늘리고, 느리면 상태를 줄인다.**
    - 차원 추가와 복사 제거는 같은 질문의 양방향이다.
4. **가장 크게 잃는 시간은 틀린 코드가 아니라 틀린 접근을 붙들고 있는 시간이다.**
    - 디버깅이 길어지는 것 자체는 신호가 아니다. 원인을 못 짚은 채 조건만 바꾸고 있는 것이 신호다.
5. **틀리는 건 로직이 아니라 조건이다.**
    - 최다빈도가 조건 누락, 그다음이 조건 오독. 인접의 정의, 간선의 방향, 입력의 순서도 전부 조건이다.
6. **파이썬 함정은 "이 이름이 무엇을 가리키나" 하나로 수렴한다.**
    - 재할당하면 지역변수가 되고, 대입하면 같은 객체를 가리킨다.

# 1. 풀이 막힘

## 지식 — 유형을 못 알아봤을 때

### 단서 → 접근
기본형(격자 BFS, 재귀 DFS, 괄호 스택)은 뺐다. 변형과 응용만 남겼다.

| 단서 | 접근 |
|---|---|
| **그래프·최단경로** | |
| "최소 몇 번 만에" 형태의 상태 변환 (숫자·문자열) | BFS (BOJ 9019, 16953, 1963) |
| 가중치가 0과 1뿐 | 0-1 BFS (`appendleft`) |
| 음의 사이클 판별 | 벨만-포드 |
| 모든 쌍 최단거리 / 경유지 문제 / V가 작음 | 플로이드-워셜 |
| 경유지가 있는 최단경로 | 구간을 나눠 각각 구해 더한다 — `(S→x)+(x→E)`, 합승이면 `(S→x)+(x→A)+(x→B)` |
| 선후관계 / 유향 사이클 판별 | 위상정렬 |
| 무향 사이클 판별 / 간접 연결도 인정 | 유니온 파인드 (BOJ 20040, 1976, 1043) |
| **탐색 범위 줄이기** | |
| 값의 범위가 매우 큼 (1000만~10억) | 이분탐색 — 범위가 큰 쪽이 탐색 대상 |
| 조건을 만족하는 가장 알맞은 값 | 파라메트릭 서치 |
| 기준을 만족하는 개수를 셈 | `bisect_right(arr, R) - bisect_left(arr, L)` |
| 구간에 반복적으로 변화를 줌 | 누적합 — `a`에 `+c`, `b+1`에 `-c` 후 누적 |
| 정렬 가능하고 양끝에서 좁혀짐 | 투포인터 |
| 길이가 고정/가변인 연속 구간 | 슬라이딩 윈도우 (r로 확장, 조건 만족까지 l로 축소) |
| 입력을 반으로 쪼갤 수 있고 `2^n`이 큼 | Meet in the Middle |
| **자료구조 고르기** | |
| "자신보다 큰(작은) 수가 나올 때까지" | 스택에 **인덱스**를 쌓다가 `while`로 `pop` |
| 힙에 최신이 아닌 값이 섞임 | 일단 넣고, 꺼낼 때 실제 상태와 일치하는 것만 처리 (lazy deletion) |
| 최댓값 K개만 필요 | min heap에 K개만 유지 |
| **수·격자 다루기** | |
| 거듭제곱이 매우 큼 | 분할정복 거듭제곱 |
| 모듈러 연산에서 나눗셈이 필요 | 페르마의 소정리 — 역원은 `a^(p-2)` |
| 격자의 테두리 처리 | 벽 한 칸 패딩 (범위 체크와 입구 탐색이 통째로 사라짐) |
| 대각선 판정 | `r - c`가 일정(주), `r + c`가 일정(역). 총 `2N-1`개 |

### 내가 놓쳤던 단서들
| 놓친 단서 | 정답 유형 |
|---|---|
| **제약조건을 안 읽음** | |
| 제한이 10억 + "가능한지 판정" / "최댓값의 최솟값" | 파라메트릭 서치 (BOJ 1939, 2343, 시험장 나누기) |
| 배열을 만들면 `2^30`칸 | 분할정복 — 해당 사분면만 재귀 (BOJ 1074) |
| 경우의 수가 유한하고 작음 (유형 16개, 조건 조합 `2^4`) | 비둘기집 / 완전탐색 (BOJ 20529, 순위 검색) |
| 값의 범위는 큰데 개수는 적음 | 좌표압축 (BOJ 18870) |
| **고정관념에 갇힘** | |
| 격자인데 이동 비용이 다름 (격자 = BFS가 아님) | 다익스트라 (BOJ 4485) |
| **모델링 단계를 건너뜀** | |
| 관계를 그래프로 바꾸면 풀린다 | 플로이드-워셜 (BOJ 1058) |
| 한 칸씩 이동도 정점을 만들면 표현된다 | 다익스트라 (BOJ 1446) |
| 최소 비용으로 전부 연결 = MST | 크루스칼 (섬 연결하기) |

## 발상 — 아이디어를 못 떠올렸을 때

### 관점을 뒤집기 (가장 반복된 발상)
막혔을 때 제일 먼저 시도할 것. 기록상 이 한 가지로 풀린 문제가 가장 많다.

- **방향을 뒤집는다**
  - **시작점과 도착점을 바꾼다** — 모든 칸에서 목표를 찾지 말고, 목표에서 출발해 거리를 기록 (BOJ 14940, 17086)
  - **역방향으로 진행한다** — S→T가 아니라 T→S, 뒤에서부터 훑으며 즉시 처리 (BOJ 12904, 11501)
  - **DP의 진행 방향을 뒤집는다** — 갈 수 있는 곳이 아니라 들어올 수 있는 곳을 본다. `dp[i][j]`를 읽지 말고 `dp[i+1][j]`를 채운다 (BOJ 1463, 11048, 17070, 카카오 코딩테스트 공부)
- **구하는 대상을 뒤집는다**
  - **최소를 최대로 바꾼다** — "옮기거나 없애야 하는 최소" = 전체 − 안 옮겨도 되는 최대. 뒤집으면 LIS가 된다 (BOJ 2565, 2631)
  - **하는 경우가 아니라 안 하는 경우를 센다** — 전체에서 틀린 답의 개수를 뺀다 (BOJ 2503, 위장)
- **수행 자체를 줄인다**
  - **여러 시작점을 큐에 한꺼번에 넣는다** — BFS를 N번 돌리지 않는다 (BOJ 2146, 17472, 7576, 등산코스 정하기)
  - **직접 수행하지 말고 상태만 기록한다** — 실제로 뒤집거나 회전시키면 시간초과. 최종 상태를 한 번에 계산하거나 인덱스만 바꾼다 (BOJ 5430, 16927, 카카오 행렬과 연산)

### 상태를 차원으로 늘리기
같은 칸이라도 상태가 다르면 다른 노드다. 이 프레임을 못 떠올려서 여러 번 막혔다.

- 벽을 부순 횟수 (BOJ 2206, 14442) / 능력 사용 횟수 (BOJ 1600) / 진입 방향 (경주로 건설)
- 집합 상태를 비트마스크로 — 방문한 도시, 발동한 함정 (BOJ 2098 TSP, 카카오 미로 탈출)
- 두 물체의 좌표 쌍을 하나의 상태로 (BOJ 13460, 블록 이동하기)

### 자주 놓친 발상
| 상황 | 떠올려야 할 것 |
|---|---|
| **격자·배열 변형** | |
| 원형 구조 | 배열을 이어붙이거나, `첫 원소 포함 / 미포함` 2케이스로 분리 (도둑질, 외벽 점검) |
| 퍼즐 조각·모양 비교 | 상대 좌표로 표현하고, 회전은 행렬 전체에만 적용 (BOJ 14500, 퍼즐 조각 채우기) |
| 격자에서 선 위로만 이동 | 모든 좌표를 2배로 늘린다 (아이템 줍기) |
| 열 단위 작업 | 열을 뽑아 리스트로 만들어 행 로직을 그대로 재사용 (BOJ 14890, 17140) |
| **정렬·우선순위** | |
| 정렬 기준이 사전순이 아님 | 커스텀 비교 함수(`cmp_to_key`). 탐색 순서로 우회하지 말 것 (가장 큰 수, 양궁대회) |
| 우선순위가 두 겹 | `(1순위, 2순위)` 튜플을 힙에 (BOJ 11286: `(절댓값, 원래값)`) |
| **트리·그래프** | |
| 경로를 출력해야 함 | 각 노드가 `prev`를 갖게 하고 끝에서 거슬러 올라간다 |
| 순회 결과로 트리 복원 | 전위의 첫 값 / 후위의 끝 값이 루트, 중위에서 좌우로 갈린다 |
| 트리의 지름 | 임의 노드에서 가장 먼 곳 → 거기서 다시 가장 먼 곳 |
| 그래프를 MST 2개로 분할 | 크루스칼 후 마지막(가장 비싼) 간선 제거 (BOJ 1647) |
| **그래도 안 보일 때** | |
| 패턴이 안 보임 | 결과를 쭉 나열해놓고 규칙을 찾는다 (드래곤 커브) |
| 예제만으로 검증이 안 됨 | 적절한 크기의 예제를 직접 만든다 |

## 유형별 각론

### DP
- **`dp[i][j]`가 무엇을 의미하는지 한 문장으로 못 쓰면 아직 못 푼 것이다.**
  - `int` 배열이어야 한다는 고정관념을 버린다 (set 배열도 가능 — N으로 표현).
  - 배열 안에 정답이 없고 행이나 열에 있을 수도 있다.
  - **축과 값의 의미를 바꿔야 하는 경우가 있다** — 메모리 범위가 1000만이면 j축을 메모리가 아니라 비용으로 잡는다 (BOJ 7579).
  - 테이블이 1억 칸을 넘으면 안 된다. 메모리 제한이 4MB급이면 일반적인 2차원 DP로는 초과하니 행 2개만 굴린다 (BOJ 2096).
- 유형을 고른다.
  - **1차원**: 가능한 모든 경우를 갱신 (동전류) / 냅색 (현재 무게까지 역순 갱신) / LIS
    - 동전류는 **루프 순서가 세는 대상을 바꾼다** — 동전이 바깥이면 조합, 금액이 바깥이면 순열 (BOJ 2293).
    - LIS는 `O(N²)` 이중 루프가 기본 (BOJ 11053). `O(NlogN)`이 필요하면 `bisect_left`로 갈아끼운다 (BOJ 12015, 12738).
  - **2차원**: 직전 선택지에 영향받음 / 진행 방향을 역으로 / 경로의 개수 / LCS / 구간 쪼개기 (`for step` → `for i` → `for k in range(i, j)`에서 `dp[i][k] + dp[k+1][j]`)
    - LCS는 같으면 `dp[i-1][j-1] + 1`, 다르면 좌·상의 max. **부분 문자열**을 찾을 땐 else를 지운다 (BOJ 5582).
  - **결합형**: DFS + DP / 트리 DP / 비트마스크 DP / 위상정렬 + DP
- 대부분 Bottom-up. 하위 문제 수가 적거나 점화식이 안 떠오를 때만 Top-down.
  - Top-down의 핵심은 "이미 계산했으면 그대로 리턴", 미방문은 `-1`로 표시.
- 필요하면 dp 배열을 2개 쓴다 (원형 구조, 뺄셈이 있어 max/min을 동시에 추적할 때, 삭제 여부를 나눌 때).

### 이분탐색·파라메트릭 서치
- 항상 두 가지를 먼저 정한다. **`이분탐색 대상`과 `범위조정 기준`.**
  - 공유기 설치: 공유기 사이 거리 / 설치한 개수
  - 입국심사: 전체 소요 시간 / 심사받은 사람 수
  - 징검다리: 바위 사이 거리의 최솟값 / 제거한 바위 개수
- **현재 `mid`가 정답이라고 가정하고 시뮬레이션한 뒤, 결과로 범위를 조정한다**는 마인드로 푼다.
- 정답이 될 수 있는 경우에만 저장한다. 조건을 만족하면 내부 for문을 조기 종료한다.

## 판정 도구

### 접근법 반례 찾기
- 그리디·DP는 **반례부터 찾고** 시작한다.
- **원인을 못 짚은 채 조건만 바꿔보고 있으면 구현이 아니라 접근을 의심한다.** 디버깅 시간은 신호가 아니다 — 자물쇠와 열쇠는 디버깅에 50분을 썼지만 접근은 맞았고, 카카오 미로 탈출은 조건만 바꿔 끼우다 결국 풀이가 틀렸다.
- 사례: 가장 가벼운 두 명을 태움(구명보트), 오른쪽부터 확인(체육복, 반례 `02021`), 회의 지속시간이 짧은 순으로 정렬(BOJ 1931), relaxation 조건만 계속 고쳤지만 애초에 풀이가 틀림(카카오 미로 탈출), 주어진 예제에서만 작동하는 로직(BOJ 16967).

### 복잡도 역산 기준선
- **재귀·백트래킹**
  - 재귀 함수는 대체로 `O(분기^깊이)`.
  - N×M 격자를 4방향 탐색하면 `O(4^(N+M))` → **N+M=15부터 10억을 넘는다.**
- **착수 전에 자릿수를 세어본다**
  - `45^6 = 83억`, `4^500`, `10만 × 10만 = 100억`.
  - `2^10`≈1천, `2^20`≈100만, `2^30`≈10억.
- **표기 주의**
  - 원소가 절반씩 줄면 `O(logN)`. 로그의 밑은 무시해도 되지만 **지수의 밑은 무시하면 안 된다.**
  - 서로 다른 대상을 같은 `N`으로 쓰지 않는다 (문자열 길이 `S`와 배열 길이 `A`는 별개, 문자열 비교에 `O(S)`가 든다).
  - 자릿수를 다루면 `O(logN)`, `while i*i <= n`이면 `O(√N)`.

### 채점 결과별 대처
- `틀렸습니다` → base case와 입력이 1줄/1개인 경우를 먼저 본다.
- `시간 초과` → **탐색 횟수를 줄일 방법**을 찾는다. 입력이 크고 정렬 가능하면 투포인터·이분탐색·그리디.
- `메모리 초과` → 공간을 추가로 쓰지 않는 방법을 찾는다.
- `런타임 에러` → 재귀 깊이, 순회 중 컨테이너 변경, 인덱스 범위.


# 2. 실수 — 구현에서 틀림

## 로직

### 조건을 빠짐없이 구현하지 않음 (최다빈도)
- 증상이 "답은 틀린데 어디가 틀렸는지 모르겠다"로 나타나 디버깅이 가장 오래 걸린다.
- **복잡한 구현 문제는 요구사항 체크리스트를 먼저 만들고, 다 짠 뒤 하나씩 대조한다.**
- 사례: 로봇을 올릴 때 내구도 미차감(BOJ 20055), 연결 안 된 톱니 미회전(BOJ 15662), `if`에 안 걸릴 때도 방향 전환해야 하는데 `if` 안쪽에 넣음(BOJ 14503), "CCTV는 CCTV를 통과할 수 있다"(BOJ 15683).

### 문제 조건 오독
- 조건 *누락*과 별개로, **읽은 내용 자체가 틀린** 경우가 반복된다.
- **입력 순서와 좌표 순서는 코드에 쓰기 전에 한 번 소리 내어 확인한다.**
  - 입력이 `m, s, d` 순인데 지문만 보고 `m, d, s`로 착각 (BOJ 20056)
  - `x, y, z` 순으로 읽어놓고 `z, x, y`로 착각 (BOJ 6593)
  - 웅덩이 좌표가 반대로 주어짐 (등굣길)
  - 그래프 입력이 정점 순서대로 들어온다는 보장이 없음 (BOJ 1167)
- **"인접"의 정의를 확인한다** — 상하좌우인지 8방향인지 문제마다 다르다 (BOJ 21608은 4방향, 17086은 8방향).
- 문제 조건을 정반대로 해석한 경우도 있다 (BOJ 9205, 12891).

### 탐색 제어
- **방문 표시 시점**
  - **시작 지점 방문 처리를 빠뜨린다** (반복 등장).
  - BFS는 꺼낼 때가 아니라 **넣을 때** 표시한다. 단, 같은 레벨의 다른 경로를 세야 하면 꺼낼 때.
  - 백트래킹은 나올 때 `visited`, `cur_list`를 직접 원상복구한다.
- **visited에 무엇을 담을지**
  - BFS는 먼저 들어온 것이 최소 시간임이 보장된다 — `visited`에 시간까지 넣을 필요가 없다.
  - 방문 여부만 필요하면 `visited`, 도달 시간·거리를 같이 저장해야 하면 `dist` 배열.
- **조기 종료**
  - **잘못 걸어 가능한 경우를 놓친다** (피로도: 자원이 모자라면 즉시 return → 뒤쪽 경우를 못 봄). 결과가 나왔다고 바로 return해도 같은 일이 생긴다.
  - 반대로 **안 걸어서 시간초과** (백트래킹이면 최적화 3요소로 간다).
- **탐색 범위 설정**
  - 조합을 만들 때는 `start`를 설정해 중복 탐색을 막는다 (순열은 항상 0, 조합은 `i+1`).
  - 중복 입력에서 중복 없는 결과를 만들 땐 결과에서 거르지 말고 **만드는 과정에서** 거른다.
  - 간선이 단방향인지 양방향인지 확인한다 (순위: 승패는 방향 정보라 단방향).
  - 같은 두 정점 사이에 **간선이 여러 개 주어질 수 있다** — 그냥 쌓지 말고 최솟값만 남긴다 (카카오 미로 탈출).

### 자료구조 성질
- **힙은 '느슨한 정렬'이다.** `heap[0]`만 최솟값이 보장되고 `heap[1]`도 마지막 인덱스도 아무 보장이 없다.
- 힙에서 `remove()`하면 힙 성질이 깨져 `heapify()`가 필요하고, 둘 다 `O(N)`이라 매우 비효율적이다. 삭제는 **유효성 배열로 표시만** 하고 꺼낼 때 무시한다 (인덱스도 함께 힙에 넣는 것이 포인트).
- 우선순위 큐 튜플은 순서를 지킨다 — `(소요시간, 정점)`을 뒤집으면 잘못 뽑힌다.
- 크루스칼은 반드시 union-find로 사이클을 판별해야 한다. 단순 set으로는 MST가 보장되지 않는다.
- 플로이드-워셜은 **경유지 `k` 루프가 가장 바깥**이어야 한다. `i`, `j`를 바깥에 두면 조용히 틀린 답이 나온다 (합승 택시 요금).

### 인덱스·경계
- **범위 검사**
  - 값에 접근하기 **전에** 범위 체크를 써야 `IndexError`를 피한다.
  - 이분탐색이 빗나가면 `< vs <=`와 `mid vs mid±1`부터 점검한다.
- **off-by-one**
  - **기존 코드를 그대로 재사용하려다 인덱스가 틀린다** (BOJ 14890: `j+1`이 아니라 `j`에서 시작해야 했음).
  - 배열 회전은 `%` 연산자로 구현한다. 직접 인덱스를 만지면 off-by-one이 난다.
  - 누적합은 구간합 배열의 첫 원소를 0으로 두고 `P[R] - P[L-1]` (1-index 기준).

### 초기값·타입·base case
- **초기값**
  - 최대엔 `-inf`, 최소엔 `+inf`, 곱셈엔 `1`. 무조건 0으로 두지 않는다.
  - `MAX`를 너무 작게 잡거나(BOJ 2294), 값의 범위가 음수까지 확장되는 걸 놓친다(BOJ 12738).
  - 초깃값을 `-1`로 두고 로직은 `INF`로 적용하는 식의 불일치를 만들지 않는다.
- **base case**
  - **잘못 잡아 입력이 한 줄/한 개일 때만 틀린다** (BOJ 1915, 1890, 2011). 확인 순서가 바뀌어도 틀린다.
- **타입**
  - **숫자 ↔ 문자 불일치가 반복된다.** dict의 key를 str로 만들고 int로 조회, str 숫자로 정렬해 첫 자리만 비교(BOJ 10814).

### 반복되는 단순 오타
- **변수를 잘못 대입한다** — `nx` 자리에 `x`, `i < min_i` 자리에 `j < min_j`, `i, j` 자리에 `team[i], team[j]`. 5건 이상 반복됐고 원인 추적이 가장 어렵다.
- **`if`를 써야 할 곳에 `while`, `while`을 써야 할 곳에 `if`.**
- **`break`를 써야 할 곳에 `return`** — 루프만 빠져나올 자리에서 함수가 통째로 끝나 결과가 비어버린다 (게임 맵 최단거리, 보물 지도).
- `and`를 써야 할 곳에 `or` — 조건은 말로 풀어 읽어서 검증한다.
- 리스트 컴프리헨션에서 `[]`를 하나 더 넣는다.

## 성능

### 백트래킹 최적화 3요소 (BOJ 15684)
1. **조기 종료를 제대로 건다** — 한 단계만 더 탐색해도 실행시간이 2배 이상 차이난다.
2. **시작 지점을 설정해 중복 탐색을 줄인다** (「탐색 제어」 참고).
3. **가벼운 자료구조를 쓴다** — `assignment` < `list append/pop` < `set add/remove` (최대 3배 차이).

### 복사·상태 관리
- **`deepcopy`를 안 해서 꼬이고(BOJ 13460, 12100), 해서 느려진다.** 둘 다 반복됐다.
  - 해결: 보드를 수정하지 말고 좌표만 들고 다닌다.
  - 해결: `prev`를 두고 swap한다 (BOJ 17144: 1100ms → 380ms).
- 배열 전체를 들고 재귀하지 말고 상태 정보만 들고 간다 (BOJ 14888).
- 그래프 상태 전체를 큐에 넣지 말고, 현재 큐 길이만큼만 처리해 레벨을 구분한다.
- 그래프 값을 직접 바꾸는 풀이는 간단하지만 확장성이 없다. 값을 못 바꾸거나 최종 상태만으로 답을 알 수 없으면 큐에 정보를 함께 넣어야 한다.

### 반복 줄이기
- 종료 여부를 매번 전체 탐색으로 확인하지 말고 카운터로 추적한다.
- 배열을 2번 돌지 말고 1-pass로 처리한다.
- 합은 매번 `sum()`을 호출하지 말고 정수 변수로 누적 관리한다.
- 후보를 전체에서 뽑지 말고 각 입력에서 나올 수 있는 것만 뽑는다 (메뉴 리뉴얼).

### 잔기술
- `visited`는 set보다 2차원 배열이 빠르다 (−1000ms). `dx`, `dy`는 처음에 한 번만 선언한다 (−300ms).
- `list.index()`는 `O(n)` → dict로 대체. 키가 고정되어 있으면 `defaultdict`보다 list가 빠르다 (BOJ 16235).
- **DFS와 BFS의 속도 차가 아니라 재귀 비용이 변수다.** 반복문이 재귀보다 7배 빠른 경우가 있다.
  - 입력이 큰 그래프에서 재귀 DFS는 시간초과 → BFS나 반복 DFS로 바꾼다 (BOJ 1325, 2573).
  - 반대로 완전탐색은 DFS가 BFS보다 빠르다 (BOJ 17070).

## 파이썬

### 스코프 — 재할당하면 지역변수가 된다 (파이썬 함정 중 최다빈도)
- 함수에서 외부변수를 **재할당(`=`)** 하면 `global` / `nonlocal`이 필수다.
- **가변객체(list)도 예외가 아니다.** 읽기·수정은 되지만, 재할당 코드가 하나라도 있으면 그 함수 안에서 지역변수로 바뀐다.
- 이름이 겹치면 내부 변수가 바깥을 가린다. 리턴할 거면 상관없지만, **원본을 수정할 거면 이름이 겹치면 안 된다.**
- 전역 `i`를 선언한 뒤 `for i in range(N)`을 돌리면 값이 바뀐다.

### 복사 vs 참조
- **재귀에서 가변객체를 저장할 때는 반드시 `[:]` 또는 `deepcopy()`** 를 쓴다.
- list의 **변경 메서드**(`sort`, `reverse`, `append`, `remove`)는 in-place라 리턴이 `None`이다. `pop()`, `index()`는 값을 리턴한다. `sorted()`, `reversed()`는 새 값을 리턴하고 `heapify()`는 in-place.
- 이중 루프 안에서 인덱스 변수 자체를 바꾸면 다음 반복에 영향을 준다.

### 순회 중 컨테이너 변경
- 순회 중인 리스트에서 `remove()`하면 원소가 당겨지며 인덱스가 밀린다. 복사본을 순회하고 원본을 삭제한다.
- **`defaultdict`를 순회하며 처음 보는 키에 접근하면 새 항목이 생성되어 `dictionary changed size during iteration`이 난다** → `list()`로 감싸서 순회한다.

### 자동 언패킹
- `deque(...)`, `set(...)` 초기화 시 값을 `[]`로 한 번 더 감싼다 — `set((0,0))`은 `{0}`이 된다. `append()`는 안전하다.
- 원소가 1개인 튜플은 `(1,)`.

### 수치
- `round()`는 round-half-to-**even**이라 `round(0.5) == 0`이다. 사사오입이 필요하면 직접 구현한다.
- 부동소수점 연산은 최대한 뒤로 미룬다 — `int((Y * 100) / X)` ○ / `int((Y / X) * 100)` ✗. 이분탐색 범위는 정수로만 다룬다 (BOJ 1072).
- 나머지 연산의 분배법칙: `(A × B) % p = ((A % p) × (B % p)) % p` — 큰 수는 도중에 나눠주지 않으면 시간초과.

### 정렬 커스텀
- `from functools import cmp_to_key` → `list.sort(key=cmp_to_key(cmp))`.
- **비교 함수는 음수/양수를 리턴해야 한다.** `return a+b < b+a`처럼 bool을 리턴하면 0/1만 나와 결과가 깨진다.
- `(값, 인덱스)`로 묶어 정렬하면 원래 위치를 추적할 수 있다.

### 입출력·재귀
- 입력 줄이 1만 개를 넘으면 `sys.stdin.readline`. 문자열이면 `rstrip()` 필수. 한 줄을 길게 받는 건 차이가 없다.
- `sys.setrecursionlimit(10**6)`. 단, 메모리 초과가 뜨면 오히려 낮춰본다.
- DFS 재귀 풀이는 PyPy3로 제출하면 메모리 초과가 나기 쉽다.

### 안 떠올라서 손해 본 관용구
- **반복·분기 정리**
  - `for-else` — flag 변수를 없앤다.
  - **함수 이름을 담은 리스트** — 긴 if-else 체인을 없앤다 (`ops[cmd-1](arr)`).
  - 2중 for문을 한 번에 탈출하려면 함수로 분리해서 return한다.
- **순회·슬라이싱**
  - `for i in reversed(range(n))` — 역순 순회.
  - `arr[:-k]` — 뒤에서 k개 잘라내기 (단 `k≠0`).
- **변환·생성**
  - `list(map(list, zip(*mat[::-1])))` — 행렬 90도 회전.
  - `deque.rotate()` — 배열 회전.
  - `itertools`: `permutations`, `combinations`, `product`(중복순열), `combinations_with_replacement`(중복조합).
